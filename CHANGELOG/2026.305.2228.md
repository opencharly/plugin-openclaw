# 2026.305.2228 — fix(params): restore the projection to the canonical cue@v0.16.1 output

## Summary

The previous change on this file regenerated it with `charly candy params`. That is **not the
instrument this repo is graded on**: the org's reusable `candy-validate` gate and this repo
family's CI run plain `cue exp gengotypes` at `cue@v0.16.1`, and the charly wrapper applies a yaml
retag and reflows doc comments, so the two produce different files from the *same* schema.

Measured with the canonical instrument against `main` after that change landed:

```
$ # splice the package clause onto candy/plugin-openclaw/schema/*.cue, then
$ cue@v0.16.1 exp gengotypes . && diff <generated> candy/plugin-openclaw/params/cue_types_gen.go
8 diff lines   → FAIL
```

The org already recorded this class in `opencharly/.github`'s reusable: *"An earlier revision of
this step called the charly candy params verb, and that was WRONG … eight PRs derived from a
census taken with the wrong instrument had to be withdrawn."* This is one of those eight, corrected
in place.

The fix restores the file to exactly what `cue@v0.16.1` emits.
